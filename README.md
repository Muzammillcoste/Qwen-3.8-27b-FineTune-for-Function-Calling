# ToolDistill-Lab

Data selection for tool-calling fine-tuning of a small language model.

**Working title:** *Quality and Diversity Versus Quantity in Small Language Model Tool-Calling
Adaptation: A Controlled Data-Selection Study*

## What this project asks

When fine-tuning a small model to produce function calls, does *which* examples you train on
matter as much as *how many*? The study compares training subsets of the same size that were
picked in different ways, and a small selected subset against a larger random one:

| Comparison | Question |
|---|---|
| `diversity_1k` vs `random_1k` | At equal size (1,000 examples), does covering more functions and argument patterns help? |
| `random_1k` vs `random_3k` | How much does tripling the data help? |
| `diversity_1k` vs `random_3k` | Can 1k well-chosen examples match 3k random ones? |

A null result is a valid outcome.

## Setup

| | |
|---|---|
| Training data | [Salesforce/xlam-function-calling-60k](https://huggingface.co/datasets/Salesforce/xlam-function-calling-60k) (60,000 rows, CC BY 4.0, gated) |
| Student model | `Qwen/Qwen3-4B-Instruct-2507`, 4-bit QLoRA (r 8, alpha 16), 1 epoch |
| Compute | Free Kaggle T4 GPU (16 GB); data prep runs locally on CPU |
| Evaluation | Held-out xLAM single-call sets (`val_eval_400`, sealed `test_eval_1000`); BFCL single-turn categories planned as external evaluation |
| Budget | No paid API calls. xLAM answers were already generated by DeepSeek-V2-Chat and Mixtral-8x22B, so this is offline supervised fine-tuning on existing teacher outputs, not logit distillation. |

## Results so far

### Data (xLAM, full 60k)

- All 60,000 rows parsed; 0 rejected. 400 exact duplicates removed.
- Teacher split matches the dataset card: DeepSeek 33,659 (56.1%), Mixtral 26,341 (43.9%).
- 97.7% of labels are strictly valid against their tool's JSON Schema. Most of the rest are
  type conflicts (e.g. a decimal in an `int` field), not clearly wrong answers.
- 25% of tool parameters carry no information about whether they are required. These are kept
  as "unknown" instead of guessing.
- Near-duplicate grouping (same query text, or Jaccard similarity ≥ 0.8) gives 52,742 groups. Splits
  are made per group so near-duplicates never cross train/val/test:
  train 47,690 / val 5,955 / test 5,955. The leakage audit passes.

Details: [reports/phase1_audit.md](reports/phase1_audit.md), [docs/DATASET_CARD.md](docs/DATASET_CARD.md).

### Training subsets

The training pool is train-split, single-call, non-duplicate records that fit in 1,536 tokens
(22,476 records). All arms are stratified the same way (teacher, number of tools, number of
arguments, length tertile, nested arguments, parameter style), so they differ only in how
records are picked inside each stratum.

| | random_1k | diversity_1k |
|---|---:|---:|
| Distinct functions | 604 | 756 |
| Total tokens | 554,547 | 555,718 (+0.2%) |
| Supervised tokens | 36,969 | 38,223 (+3.4%) |
| DeepSeek share | 0.585 | 0.585 |
| Optimizer steps | 125 | 125 |

`diversity_1k` greedily prefers records that add an unseen function, an unseen argument
signature, or new query words, and never takes two records from the same duplicate group.
A fourth arm (schema-consistent records only) was dropped because it differed from
`random_1k` in only 4.3% of examples.

Details: [reports/phase2_selection.md](reports/phase2_selection.md),
[docs/SELECTION_METHODS.md](docs/SELECTION_METHODS.md),
[reports/phase3b_readiness.md](reports/phase3b_readiness.md).

## Evaluation

The scorer (`eval-v2`) was frozen before any training arm was evaluated. It parses
`<tool_call>` blocks as JSON (no code execution) and reports:

- exact call accuracy (tool name + arguments), primary metric
- parse rate, tool-name accuracy, per-argument accuracy, hallucinated-tool rate
- paired comparison between models: McNemar test and bootstrap confidence intervals

The test set (`test_eval_1000`) is sealed and kept out of the Kaggle bundle until the main
comparisons on the validation set are finished. See
[docs/EVALUATION_SPEC.md](docs/EVALUATION_SPEC.md).

## Repository layout

```
configs/      YAML configs for data, selection, training and evaluation
src/tooldistill/
  normalize_xlam.py, validate.py      parse xLAM rows into a common schema and check labels
  deduplicate.py, split.py            duplicate grouping and group-aware splitting
  provenance.py                       teacher model from original row ID
  audit.py, token_lengths.py          data audit report
  select.py, phase2.py, analysis.py   subset selection and balance tables
  format_qwen.py, train.py, infer.py  Qwen chat template, QLoRA training, generation
  evaluate.py, stats.py, compare.py   scoring and paired statistics
  kaggle_export.py, phase3a.py, phase3b.py   Kaggle bundles and run drivers
scripts/      thin command-line wrappers around src/tooldistill/cli.py
notebooks/    Kaggle notebook (generated by build_notebook.py)
tests/        pytest suite; runs on a small synthetic fixture, no data access needed
reports/      audit reports, subset manifests (IDs + hashes), eval set manifests
docs/         protocols, dataset card, experiment log
```

Raw data, model weights and run outputs are not committed (xLAM is gated; see
[LICENSE_NOTICES.md](LICENSE_NOTICES.md)). Subsets and eval sets are stored as ID lists with
SHA256 hashes, so they can be rebuilt exactly from the original dataset.

## Running it

Local (CPU):

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    Linux/macOS: source .venv/bin/activate
pip install -r requirements-local.txt
pip install -e .
pytest -q
```

Try the pipeline on the synthetic fixture (no Hugging Face access needed):

```bash
python scripts/prepare_dataset.py --input tests/fixtures/miniature_xlam.jsonl --out data/normalized/fixture --fixture
```

Full data (accept the dataset conditions on Hugging Face, then `hf auth login`):

```bash
python scripts/check_access.py
python scripts/download_xlam.py --config configs/data.yaml
python scripts/prepare_dataset.py --config configs/data.yaml --seed 42
python scripts/audit_dataset.py --config configs/data.yaml
python scripts/audit_selection.py --config configs/research.yaml
python scripts/export_phase3b.py
```

Training and evaluation run on Kaggle with `notebooks/kaggle_train_eval.ipynb`: set `MODE`
and `RUN_ID` in the first cell and run all. Step-by-step instructions are in
[docs/KAGGLE_GUIDE.md](docs/KAGGLE_GUIDE.md). Downloaded outputs are compared locally with
`scripts/summarize_results.py`.

## Limitations

- xLAM is already filtered by its authors (>95% correct on their sample), so this study is
  about selection and quantity, not about fixing bad labels.
- xLAM has no "no tool needed" examples, so abstention is not a trained skill here.
- One training seed per arm; confidence intervals cover test-sample variation only.
- The internal test set is mostly in-distribution (only 2.9% of test calls use a function
  absent from the training pool). Generalization to unseen tools depends on the BFCL evaluation.

Full protocol: [docs/RESEARCH_PROTOCOL.md](docs/RESEARCH_PROTOCOL.md). Running log of decisions:
